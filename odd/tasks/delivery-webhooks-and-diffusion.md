# delivery-webhooks-and-diffusion

Objective: add the two remaining proposal candidates — (D) delivery status webhooks (client systems get notified when an email reaches SENT/WARNING/FAILED, signed HTTP POST with automatic retry) and (E) diffusion masiva (bulk send with the daily rate limit and queue-driven sending).

Branch: `feat/webhooks-diffusion` (from `feat/platform-expansion`). Delivery: single feature branch, work-unit commits, Conventional Commits (Spanish). Push/PR: user decision.
Test runner: `pnpm test` (colocated specs, `import 'reflect-metadata';` first when class-validator is touched) + `pnpm test:e2e`. DB still down: schema additions generated offline (`prisma validate` + `prisma generate`), migration pending like previous features.

## Specs

- **S1** Two new Prisma models (uuid v4 strictly DB-side with `@default(dbgenerated("gen_random_uuid()"))`):
  - `webhook_endpoints`: `id_endpoint BigInt @id @default(autoincrement())`, `endpoint_uuid String @unique @db.Uuid @default(dbgenerated("gen_random_uuid()"))`, `id_client BigInt`, `url String @db.VarChar(500)`, `secret String @db.VarChar(255)` (random hex generated in code — a secret is not a uuid), `is_active Boolean @default(true)`, timestamps.
  - `webhook_deliveries`: `id_delivery BigInt @id @default(autoincrement())`, `id_endpoint BigInt`, `id_email BigInt`, `event String @db.VarChar(20)` (SENT/WARNING/FAILED), `attempt Int @default(0)`, `ok Boolean?`, `status_code Int?`, `error String? @db.VarChar(500)`, `next_retry_at DateTime?`, timestamps. Index `(next_retry_at)`.
- **S2** EmailAttemptService hook: after an attempt transitions an email to SENT, WARNING or FAILED, enqueue one `webhook_deliveries` row per ACTIVE endpoint of that email's client (id_client), event = final state. Nothing is sent synchronously; failures while enqueuing must not break the send result. Sent with no endpoints → no rows.
- **S3** Webhook delivery worker: `WebhookDeliveryScheduler` (same pattern as `EmailRetryScheduler`, own 30s interval, fail-closed idempotent tick) picks due deliveries (`next_retry_at <= now`, not-yet-delivered), POSTs the payload JSON to the endpoint URL with headers `X-Nexlify-Event`, `X-Nexlify-Delivery` (id) and `X-Nexlify-Signature` = HMAC-SHA256(raw body, endpoint secret) via an injectable HTTP sender, records `ok` + `status_code` + attempt; on 2xx → delivered (`ok=true`, clear `next_retry_at`); else `next_retry_at = now + 60s*attempt`, max 3 attempts then gives up with `ok=false`. 1xx/4xx/5xx/timeouts are failures.
- **S4** Webhook management endpoints (AuthGuard accepts JWT **or** X-API-Key via the existing dual `EmailAuthGuard`):
  - `POST api/webhooks` — register `{ url }` for the calling client (admin may pass `id_client`); secret returned exactly once.
  - `GET api/webhooks/my` — list own endpoints (url, uuid, is_active; secret masked/never).
  - `PUT api/webhooks/:endpointUuid` — update url/is_active (own or admin).
- **S5** Diffusion masiva:
  - `POST api/email/diffuse` (EmailAuthGuard + ConfigurationExistsGuard): body `{ to: string[] (1..500), subject, html?, text? }`; respect the remaining daily budget (daily_send_limit − SENT/WARNING today); creates one QUEUED `emails` row per recipient (short_code, NO immediate send); returns `{ queued: number, short_codes: string[] }` and `4xx`/error when the target count exceeds the remaining budget.
  - Scheduler extension: `RetryDueEmailsUseCase` now also processes `QUEUED` emails (pending first send, no `next_retry_at` constraint) **before** retries, always capped by the remaining daily budget per tick; a QUEUED email that fails enters the normal retry state machine.
- **S6** README (endpoints + tables + messaging flow) and feature-doc closure; all colocated specs + e2e green (add any new model names used by requests to the e2e mocked Prisma provider); `prisma validate`+`generate` OK offline.
